GUIDED LOCAL TRAINING

Who can read this record?

Learn the difference between being signed in and being allowed access.

The experiment

Account A and Account B each own a synthetic private record. Both can sign in, but only the owner should be allowed to read their record.

  1. Check that A can read A’s record and B can read B’s record.
  2. Check that an anonymous request is rejected.
  3. Ask for A’s record using B’s test credentials.
  4. Repeat the same checks against the fixed API.

The broken version checks authentication but forgets ownership. The fixed version checks both. A 200 response only confirms the flaw when the exact private record matches and the baseline controls are valid.

What to learn from the result

Authentication: Which account made the request? Authorization: Is that account allowed to read this record?

The broken version should expose A’s exact synthetic record to B. The fixed version should return 403. Unexpected controls, errors, unrelated content or a login page are inconclusive.

This is a controlled lesson, not a live-target vulnerability report. You can reopen or export it from assessment history without running the requests again.
